① Análise
- Lê AGENTS.md, .agents/, código existente para entender o contexto do projeto.
- Opcional: invoca business-rules para extrair e validar regras de negócio do domínio.
- Opcional: invoca ideas-agent para explorar alternativas de design, arquitetura, tecnologias e trade-offs.
- Resultado: entendimento claro do contexto, restrições e requisitos.
② Decomposição
- Transforma o objetivo em tarefas atômicas, cada uma com:
- Descrição clara do que implementar
- Tipo: code, test, config, doc ou explore
- Dependências entre tarefas (se houver)
- Subagent_type para code/test/config é sempre "code-workflow"
- Tarefas explore são executadas diretamente pelo lead-dev-agent.
- Resultado: lista ordenada de tarefas com dependências resolvidas.
③ Validação de escopo pré-código
- Invoca scope-guard-agent para cada tarefa.
- Classificações:
- Aprovado: segue para execução.
- Borderline: avalia a justificativa e decide (aprovar, esclarecer com usuário, ou bloquear).
- Bloqueado: remove a tarefa do plano e reporta ao usuário.
- Resultado: plano filtrado apenas com tarefas válidas e no escopo.
④ Apresentação do plano
- Exibe o plano completo (tarefas, ordem, dependências) para o usuário.
- Aguarda confirmação explícita antes de iniciar a execução.
- O usuário pode ajustar, reordenar ou cancelar tarefas.
- Resultado: plano aprovado e pronto para execução.
⑤ Execução orquestrada
- Delega cada tarefa ao code-workflow via ferramenta Task.
- Paralelismo: máximo de 3 code-workflow simultâneos (respeitando dependências).
- Tarefas doc são delegadas ao agente doc (não ao code-workflow).
- Acompanha progresso via todowrite.
- Resultado: tarefas executadas em paralelo com resultados parciais consolidados.
⑥ Verificação cross-task
- Verifica consistência entre tarefas:
- Naming: convenções consistentes entre arquivos.
- Padrões: mesmos padrões de projeto/style guide.
- Lint: sem regressões de lint no conjunto.
- Segurança: sem secrets/PII expostos no diff.
- Escopo: implementação não extrapolou o escopo acordado.
- Resultado: validação cruzada aprovada ou lista de correções necessárias.
⑦ Relatório final
- Consolida resultados de cada tarefa:
- Tabela com tarefa, status (sucesso/falha/parcial), fases concluídas.
- git diff --stat mostrando arquivos alterados com +/-.
- Para cada code-workflow: status de Lint e Test (Fases 3 e 6).
- Notas sobre riscos, decisões e pendências.
- Resultado: relatório final apresentado ao usuário.
Critérios de aceitação por tarefa
1. Subagente reportou sucesso.
2. Relatório Fase 9 do code-workflow mostra Lint e Test (ou justificativa válida).
3. git diff --stat mostra apenas os arquivos esperados.
4. Nenhum secret/PII no diff.
5. Escopo preservado (validação cross-task).

Falha de implementação

Integração com code-workflow
Task {
  subagent_type: "code-workflow",
  prompt: "
    Objetivo: <descrição clara da tarefa>
    Contexto: <links para arquivos, regras de negócio>
    Critérios de aceitação: <lista específica>
    Tipo: code | test | config
    Depende de: <tarefas anteriores, se houver>
  "
}
O lead-dev-agent não interfere nas 9 fases internas do code-workflow — apenas avalia o relatório final (Fase 9) e aplica os critérios de aceitação.
Convenções Zflow (quando aplicável)
- Branches de feature: feature/id-do-card a partir de development
- Branches de fix: fix/id-do-card a partir de development
- Hotfixes: hotfix/descricao-curta a partir de main
- Commits: Conventional Commits (feat:, fix:, docs:, refactor:, chore:)
